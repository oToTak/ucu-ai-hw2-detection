# Kaggle: інструкція для автора

Ноутбук `hw2.ipynb` клонує репозиторій з GitHub, тож Kaggle бере **запушений** код. Перед кожною сесією: коміт і пуш (воркери не комітять; оркестратор питає тебе на воротах).

## Налаштування ноутбука (один раз)

1. Новий Kaggle-ноутбук з `hw2.ipynb`, додати змагання як Input, Accelerator: GPU T4 x2 або T4 (не P100: новий образ може його не підтримувати), Internet: On.
2. Секрет `WANDB_API_KEY` (Add-ons → Secrets), якщо B2.
3. Сесій може бути дві одночасно (два GPU-ноутбуки): це дає паралельні лейни.

## Як запускати

1. У першій клітинці змінюєш лише `COMPUTE` і `SMOKE`:
   - `COMPUTE = ["10_frcnn_base", "11_frcnn_rpn"]`, шаблони теж працюють: `["1?_*"]`.
   - `SMOKE = True`: швидка перевірка (результат у `results/_smoke/`).
2. Save Version → Save & Run All. Ліміт 12 год на запуск, тому на сесію ≤4–5 год.
3. Після завершення: Output → завантажити `light.zip` (метрики, csv, png, конфіги, логи) і розпакувати в `workspace/results/`. Ваги (`*/weights/best.*`) лиши в Output: для T7/B1/B2 їх треба повернути на Kaggle як Dataset `hw2-weights` (Add Input).
4. Зелений статус Kaggle не гарантує успіху всіх ранів: без `SMOKE` упалий ран іде у список збоїв, а сесія йде далі, і `light.zip` оновлюється після кожного рану. Тому наприкінці перевір список збоїв у виводі ноутбука. Якщо впав ран: надішли оркестраторові останні ~15 рядків `results/<ран>/log.txt` (ноутбук друкує їх сам).
5. Public score з Kaggle запиши в `results/<ран>/public_score.txt`.

## План сесій

| Сесія | `COMPUTE` | `SMOKE` | ≈ год | Коли |
|---|---|---|---|---|
| K0 | `["0?_*", "1?_*"]` | True | 0.2 | після G1 |
| K0b | решта родин, що вже мають код | True | 0.3 | по мірі готовності хвиль |
| K1 | `["05_baseline", "1?_*"]` | False | ≈4.5 | 07.11 |
| K2a / K2b (паралельно) | `["2?_*"]` / `["3?_*"]` | False | ≈4 / ≈4 | 08.11 |
| K3 | `["4?_*"]` | False | ≈4 | 09.11 |
| K4 | `["5?_*"]`, `["6?_*"]`, `["7?_*"]`, `["8?_*"]` | False | ≈5 | 09–10.11 |

Ран `*_compare`/`*_summary`/`00_eda`/`60_temporal` рахуються на CPU, вмикай їх у ноутбуці без GPU.

## Чекліст review на G1 (для RV)

1. Жодного абсолютного шляху, жодного запису в `/kaggle/input`.
2. Усі гіперпараметри з yaml; seed з протоколу; ран пише `metrics.json`, `train_log.csv`, `per_size.csv`, `per_class.csv`, `preds_val.json.gz`, `weights/best.*`, `submission.csv` (у SMOKE теж).
3. `SMOKE` справді ≤3 хв і не змінює формат виходів.
4. `requirements.txt`: немає `torch`, `torchvision`, `numpy`; версії пінені; немає конфліктів між лейнами.
5. Оцінка лише через `src.evaluator`; класи 0–7 у сабміті; до 500 детекцій на кадр; координати в пікселях оригіналу.
6. Тренувальний цикл не тримає весь датасет у RAM; DataLoader `num_workers` ≤ 4 (Kaggle має 4 vCPU); AMP ввімкнений там, де безпечно.
7. Ігнор-регіони: оцінювач не штрафує детекції в них; у тренуванні обробка описана в `src/CLAUDE.md`.
8. `pipeline.compute` при помилці друкує хвіст `log.txt`; `show()` не падає на відсутніх файлах.
9. `.gitignore` не пропускає ваги, пропускає легкі результати (мегабайти, не сотні).

Review повертає список правок із власниками (за таблицею в `PLAN.md`), а не правки сам.
