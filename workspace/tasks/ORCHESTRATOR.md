Читай лише: `workspace/CLAUDE.md`, цей файл, `PLAN.md`, `STATE.md`, `DECISIONS.md`, `workspace/LOG.md`. Далі працюй за `STATE.md`. Не читай `src/`, `results/`, `teachers-things/`: це контекст воркерів.

## Контекст оркестратора

- В голові тримаєш лише: що готово, що біжить, що чекає на автора. Решта живе у файлах.
- Воркер повертає ≤150 слів, деталі пише в `tasks/handoff/<лейн>.md`. Handoff не читай; наступному воркеру передаєш **шлях**, а не вміст.
- Після кожної зміни стану оновлюй `STATE.md` (один-два рядки). Це єдине джерело правди після `/clear`.
- Якщо контекст став важким: онови `STATE.md`, скажи авторові зробити `/clear` (або `/compact`) і продовжуй зі `STATE.md`.

## Як запускати воркерів

- Інструмент `Agent`, `subagent_type: "general-purpose"`, `model` з таблиці в `PLAN.md`. Параметр `effort` не став, поки автор сам не попросить.
- Незалежні воркери з однієї хвилі запускай **в одному повідомленні** (кілька викликів `Agent` одразу). Вони йдуть у фоні, результат приходить сповіщенням. Не опитуй і не чекай.
- Шаблон промпту воркера:

```
Ти воркер лейну <ЛЕЙН>, таск <ID>. Прочитай по порядку: workspace/CLAUDE.md, workspace/src/CLAUDE.md,
workspace/tasks/_common.md, workspace/tasks/<файл таску>, workspace/tasks/handoff/<ЛЕЙН>.md (якщо є).
Виконай блок «Оркестрація» таску. Правила в _common.md обов'язкові (власні файли, мінімум тестів, handoff, LOG).
Рішення, позначені в DECISIONS.md, вже прийняті: <стислі значення D1…>.
Відповідь: ≤150 слів (готово / run_id для Kaggle / що має зробити автор / ризики / чи контекст важкий).
```

## Продовжити воркера чи запустити нового

- **Той самий контекстний блок** (див. «Лейни» в `PLAN.md`): продовжуй `SendMessage` тому ж агентові (інструмент `SendMessage`, завантаж через `ToolSearch` з `select:SendMessage`). Він вже тримає потрібні файли в голові.
- **Інший блок** або воркер у звіті написав «контекст важкий»: новий `Agent` (це аналог `/clear`). Передай шлях до його `handoff/<лейн>.md`.
- Після помилки з Kaggle: `SendMessage` власникові файлу з потрібним шматком traceback (десяток рядків, не весь лог). Власник — за таблицею файлів у `PLAN.md`.
