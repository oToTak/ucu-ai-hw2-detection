# Handoff EDA (T1b)

**Зроблено:** `src/eda.py` (runner `eda`), `configs/00_eda.yaml`. Повний ран пораховано локально (38 с, CPU): `workspace/results/00_eda/` (`metrics.json`, `per_clip.csv`, `plots/`: classes, sizes, resolutions, density, clips_scatter, clips_class_mix, ignore, small_share, anchors, boxes_check, boxes_zoom; 3.4 МБ, у git може йти). Рамки на 6+1 кадрах перевірено очима: збігаються з об'єктами, ignore-регіони лягають на натовпи. На Kaggle перераховувати не треба; `show("00_eda")` покаже збережене. Smoke не запускався (за вказівкою); у коді гілка `smoke` бере `smoke_subset(2 кліпи, 64 кадри)`.

**Розміри «після ресайзу»:** довга сторона → `imgsz`=960. «Мале» = площа рамки <32² (COCO). Усі числа нижче з `metrics.json`.

## Спостереження → рішення
1. **Малі об'єкти:** у пікселях оригіналу <32² це 24.9 % train / 19.2 % val, але після ресайзу до 960 уже 73.5 % / 70.0 % (медіана sqrt(площі) 22.8 px, p5 10 px). Анкери/рівні FPN рахувати для розмірів при 960; P2/stride-4 голова чи вищий `imgsz` (1280) і SAHI варті експерименту (T4/T5/T7). 640 було б гірше.
2. **AP_small не переноситься на test.** Роздільності: train 1344–2720, val 1344–3840 (3840×2160 це один кліп, 34 % кадрів val), test 680–1920 (11 кліпів 1920×1080, 18 кліпів 1360×764, 3 кліпи 680×382). Проєкція з відносних розмірів train+val на довгі сторони test: ≈45 % (за об'єктами) / 40 % (за кліпами) об'єктів <32² в оригіналі, проти 19 % у val. Для 680/960 це 87 % / 73 %. Висновок: val-AP_small оптимістичний, а AP_50:95 на val треба читати разом із per-resolution. У звіті прямо назвати як обмеження. Кліпи 680/960 апскейляться до 960 (8 % кадрів test), деталей там нема: SAHI чи TTA їм не допоможе, а multi-scale під час тренування допоможе. Для оцінки на val варто додати розріз за роздільністю (запит автору/F, не зроблено).
3. **Густина:** train середнє 45.7, p95 118, p99 142, max 180 об'єктів на кадр; val p95 103, max 116. `num_queries` для RT-DETR/DETR: 300 з запасом (≈1.7× max); `max_det`=500 з протоколу ніколи не обрізає (жоден кадр >300). Різка різниця між кліпами: від 5 до 143 об'єктів на кадр.
4. **Класи:** train: car 45.7 %, person 29.7 %, motor 9.3 %, van 4.2 %, tricycle 3.7 %, bicycle 3.6 %, truck 2.8 %, bus 0.9 % (9.6k). Val зсунутий: person 44 %, car 28 %, bus 0.2 % (264 об'єкти), truck 1.2 %. Per-class AP для bus/truck на val шумний (264 об'єкти bus на 7 кліпах). Рішення: не лишати без уваги баланс (class-weights/repeat-factor лише якщо час є); у звіті рідкісні класи інтерпретувати обережно.
5. **Анкери (k=9, IoU-k-means при 960):** (8,11) (10,20) (17,15) (15,29) (22,24) (31,17) (29,40) (48,27) (76,55) px, середній найкращий IoU 0.73. Стандартні COCO-анкери (від 32 px) не годяться: для RetinaNet (T4) замінити розміри на ≈8–80 px, для YOLO anchor-free не критично. Гістограма розмірів у `metrics.json: size_histogram_after_resize`; 87 % об'єктів у 8–48 px.
6. **Ignore:** регіони є у 74.8 % train-кадрів і 50.4 % val (у середньому 2.6 і 1.4 на кадр); займають в середньому 2.9 % площі кадру train (де є: 3.9 %, p95 11.8 %, максимум кліпу 27 %). Відкидається з тренування 1.07 % train-об'єктів (11 883, `src/CLAUDE.md` казав ≈1.3 %: різниця у способі підрахунку, критично не впливає). Рішення F (заливка + відкидання) лишається.
7. **Тренувальна вибірка:** `frame_step=3` дає 8090 кадрів; процентилі густини вибірки збігаються з повним train (p95 118, max 180), тож крок 3 не зсуває розподіл; сусідні кадри кліпу сильно корельовані, тому ефективний обсяг даних менший за кількість кадрів (аргумент не збільшувати епохи без аугментацій).
Додатково: occlusion train 0/1/2 = 54/40/5 %, truncation=1 лише 4 %.

## Що знати наступним
- `metrics.json` ключі: `splits`, `classes`, `sizes{by_split, by_class, by_resolution, percentiles_size_after_resize}`, `objects_per_frame`, `ignore`, `anchors`, `size_histogram_after_resize`, `test_projection`, `small_share_summary`, `occlusion`, `truncation`, `box_check_frames`.
- Локально (Windows, cp1251) фінальний `print` у `pipeline.compute` (`→`) падає з UnicodeEncodeError після завершення рану; запускати з `PYTHONIOENCODING=utf8`. Файли тоді повні. На Kaggle не проявляється. Правка (прибрати стрілку чи reconfigure stdout) потрібна у `pipeline.py` (лейн F), необов'язкова.
- `boxes_zoom.png` показує лише train (у val немає кадрів 3840 із ≥30 об'єктами).
- Проєкція test припускає ті самі сцени за відносним розміром: оцінка, не факт.
**Правки чужих файлів:** лише необов'язкова правка `pipeline.py` вище. **requirements:** нічого не додавав.
